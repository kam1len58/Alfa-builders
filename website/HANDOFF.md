# Передача и проверка запуска

Нужны Node.js 24.22.1+, pnpm 11.25.0, .NET SDK 10. Для импорта CSV - Python 3.10+ без дополнительных библиотек. backend клонируется отдельно по инструкции README. Секреты, исходные CSV, профили и рабочие результаты держать вне Git.

## Все крупные компании

Из website/ собрать профили:

```sh
python analytics/build_profiles.py --companies /private/data/df_Uid_data_hack.csv --payments /private/data/df_Uid_payment_hack.csv --links /private/data/df_Fid_Uid_link_hack.csv --output /private/runtime/profiles.json
```

В .env.local указать PROFILES_FILE=/private/runtime/profiles.json. Альтернатива: DATASET_DIR=/private/data и PYTHON_EXE=python; npm start сам повторит сборку. В Windows использовать свои абсолютные пути, в Linux обычно python3. Путь к файлу профилей должен находиться вне checkout.

Обрабатываются все строки трёх файлов. По умолчанию выбираются компании с выручкой строго больше 15 млрд руб. Для иной компании добавить --ids U_123 U_456; --min-revenue 0 расширяет выборку. При большом каталоге учитывайте память агрегации платежей.

Пустые банковские признаки остаются null. Контрагенты объединяются по ID и направлению платежей, суммы и числа платежей складываются; доля считается от платежей соответствующего направления. Для связей физических лиц используется пересечение ID, без предположений о юридическом контроле. Поля supplier/customer сохранены для совместимости: фактически это получатель/плательщик. ОКВЭД-позиция относится к датасету, не ко всему рынку.

Повторяющийся ID с несовместимыми реквизитами помещается в quarantinedIds. Из его строк не выбирается случайная «правильная». Статистика, SHA-256 исходников и время сборки находятся в JSON профилей. Переданные demo_profiles.json не перезаписываются.

## Проверка с нуля

1. В новой папке получить сайт и backend, установить зависимости через npx pnpm@11.25.0 install --frozen-lockfile. Не копировать node_modules, .env.local, базы или ключ другого участника.
2. Запустить npm run check, npm test и python analytics/test_profiles.py.
3. Собрать профили, задать PROFILES_FILE и BACKEND_PATH; выполнить npm start. Без ключа лента и источники должны работать, генерация должна явно сообщать об отсутствии настройки.
4. Проверить наличие 115 компаний, поиск по ID, открытие новой компании вне четырёх демо, сортировку и источники. Для AI использовать свой разрешённый ключ через окружение.
5. Выполнить сценарий DEMO.md; сохранить версии среды, дату, количество компаний и результат отдельно от Git.

Чистая папка на той же машине проверяет скрытые зависимости файлов, но не заменяет проверку на другом компьютере/ОС.

## Docker

Нужен работающий Linux Docker Engine и Compose 2.17+. Отсутствие Docker или WSL не считается успешным контейнерным запуском. В .env.local указать:

```dotenv
ALFA_ACCESS_FILE=/private/access.json
ALFA_PROFILES_DIR=/private/runtime
CONTAINER_PROFILES_FILE=/profiles/profiles.json
# BACKEND_CONTEXT=/path/to/backend/NewsAnalytics
```

Файл доступа создаётся scripts/create-access.mjs вне Git. Пароль передаётся через ALFA_NEW_PASSWORD, не в аргументах команды. Контейнер получает файл только на чтение. Не переносить личный файл учётных записей в репозиторий.

```sh
docker compose --env-file .env.local config --quiet
docker compose --env-file .env.local up --build -d
docker compose --env-file .env.local ps
```

Открыть http://127.0.0.1:4173, войти и пройти DEMO.md. Порт API наружу не опубликован. Healthcheck проверяет сессию сайта и список компаний API внутри сети контейнеров; он не измеряет качество модели. Скрипт дополнительно проверяет ID/состояние контейнеров и обращается из контейнера сайта к API, чтобы не принять за результат уже работающий локальный сайт. Для остановки использовать docker compose down без удаления томов. Изменение схемы C# может потребовать согласованной миграции базы; старые тома автоматически не удаляются.

node scripts/verify-delivery.mjs проверяет предпосылки; флаг --docker выполняет сборку и запуск. Проверка не требует ключа модели. После проверки контейнеры остаются запущенными для демонстрации.

## Проверка сканированного PDF

```sh
node scripts/extract-pdf.mjs /private/source.pdf /private/extracted.json 6
```

Результат содержит текст страниц, способ извлечения, confidence OCR, SHA-256 и truncated. OCR выполняется локально, без внешнего сервиса. Он не подтверждает точность цифр, дату или принадлежность документа банку. Новый/изменённый PDF в сборщике остаётся review_required до проверки атрибуции и коротких цитат. Для неизвестных файлов действует лимит 12 МБ; увеличенный лимит 40 МБ задан только для известной крупной стратегии кейса.

## Экспертная оценка

С настроенными APP_DATA_DIR, PROFILES_FILE и LLM_CACHE_DIR:

```sh
node scripts/prepare-review.mjs /private/review
node scripts/prepare-review.mjs /private/review --generate
node scripts/score-review.mjs /private/review/review.json
```

Без --generate платных вызовов нет. С флагом запрашиваются не более 20 разборов на локальном сервере; это расходует бюджет команды. Набор - top-5 четырёх разных разделов ОКВЭД и отдельные скрытые новости для поиска пропусков. Эксперт получает review.html и полный review.json, оценивает первоисточники и заполняет reviewer, relevant, factsCorrect, actionsUseful, bankAttributionCorrect и comment. Пустые оценки остаются null. Не менять состав выборки после просмотра оценок.

Итоговые метрики показывают знаменатели и не считают пустые оценки положительными. Для полноценной независимости эксперт не должен участвовать в настройке правил по этой выборке. В рабочем интерфейсе доступны отдельные критерии оценки и учётная роль expert. Их заполнение само по себе не заменяет независимый процесс проверки.

Версия сайта: 0.3.0. Перед демонстрацией сверить API_CONTRACT.md и DEMO.md. Файл release-manifest.json комплекта фиксирует SHA-256 исходников и базовый коммит; незакоммиченные изменения отмечаются явно. Наличие комплекта не означает отправку в GitHub или запуск Docker на другом компьютере.
