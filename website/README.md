# Альфа-Бизнес

Персональная новостная лента, подключённая к API проекта NewsAnalytics. Поиск, фильтры, подробности и сохранённое работают в браузере; компании, новости, оценки и объяснения поступают с бэкенда. Сервер сайта также подключает модель для персонального разбора и диалога по событию.

Краткая инструкция с получением обеих веток находится в [корневом README](../README.md).

## Локальный запуск

Нужны Node.js 20.6+ и .NET SDK 10. Бэкенд из ветки `backend` и сайт из `Damir-website` можно держать в отдельных папках. C#-код для подключения сайта менять не требуется.

1. В первом терминале из корня копии ветки `backend` запустить API:

```powershell
$env:ASPNETCORE_ENVIRONMENT = 'Development'
dotnet run --project NewsAnalytics/NewsAnalytics/NewsAnalytics.API.csproj --no-launch-profile --urls http://127.0.0.1:5194
```

Запускать из исходников: текущая конфигурация `dotnet publish` бэкенда не включает `golden_news.json`, из-за чего опубликованная сборка не загружает новости и аналитику.

2. Во втором терминале перейти в `website/` и запустить сайт:

```sh
npm run dev
```

Открыть http://127.0.0.1:4173. Установка JavaScript-зависимостей и сборка сайта не нужны.

## Как устроено подключение

Браузер обращается к `/api/Companies`, `/api/Companies/{id}` и `/api/Companies/{id}/feed` на адресе сайта. `server.mjs` передаёт GET/HEAD-запросы в API; CORS на стороне бэкенда не нужен. Изменение данных через этот прокси не разрешено.

При смене компании профиль и лента загружаются заново. Предыдущий запрос отменяется, чтобы запоздавший ответ не подменил выбранную компанию. Баллы, разделы и объяснения отображаются из ответа бэкенда без пересчёта. Неизвестные ранее ID новостей поддерживаются.

Если API недоступен, сайт показывает ошибку и кнопку повторной загрузки. Подмена ответа сохранённой демо-лентой не выполняется. Сохранённые события разделены по компаниям и хранятся в localStorage браузера.

## Возможности интерфейса

- В разборе четыре вкладки: событие, влияние, рекомендации и источники. По кнопке «Подготовить разбор» модель формирует персональное объяснение, условные риски, возможности и действия. Исходный текст, правила, выводы модели и банковская позиция разделены.
- Фильтры по периоду публикации (обе даты включительно), теме, продукту для обсуждения и разделу важности. Они сочетаются с поиском и сохранённым. Неверный период выводит ошибку; фильтры можно убрать по одному или сбросить.
- Сравнение одной новости в лентах всех компаний. Отсутствующая новость означает «не возвращена API», а не нулевой балл. Ошибка одной компании не мешает остальным; есть повторный запрос и обновление. Сравнение загружает оценки отдельно и не меняет основную ленту.
- Экспорт показанных или отмеченных карточек в CSV (UTF-8 с BOM, разделитель `;`) и JSON. Отмеченные карточки сохраняются при фильтрации, выбор сбрасывается при смене компании. CSV нейтрализует формулы из текстовых полей. Если разбор подготовлен, выгрузка включает выводы модели, основания и время генерации. Полный исходный профиль и таблицы платежей не выгружаются; текст разбора может содержать использованные агрегаты профиля.
- Обратная связь «Полезно», «Не подходит», «Есть ошибка» и комментарий до 1000 символов. Хранится отдельно для пары компания/новость в этом браузере, доступна в экспорте. На сервер не отправляется и на ранжирование не влияет.
- Диалог с моделью учитывает текущую компанию, событие, проверенный разбор и последние шесть пар сообщений. История последних десяти ответов хранится в этом браузере отдельно для пары компания/новость. Сохранённые ответы относятся к моменту их генерации; новые запросы используют текущие данные сервиса. При ошибке нет подмены ответа заготовленным текстом.

При запрете localStorage обратная связь и диалог продолжают работать в памяти страницы с уведомлением об ограничении. Кнопки удаления позволяют убрать оценку или историю конкретного события. Вкладки поддерживают стрелки, Home/End и управление с клавиатуры; диалоги закрываются Escape.

Адрес API можно изменить перед запуском сайта:

```powershell
$env:BACKEND_URL = 'http://127.0.0.1:5194'
npm run dev
```

Порт сайта задаётся переменной `PORT`. Оба сервера следует оставлять доступными только локально, пока не настроены права доступа к данным.

## Подключение модели

Используется OpenAI-compatible API организаторов. Запросы отправляет сервер Node.js, C#-код бэкенда менять не требуется. Значения по умолчанию: `https://changellenge.up.railway.app/v1` и `deepseek/deepseek-v4.1-flash`. Ключ считывается только из переменной окружения `LLM_API_KEY`.

Для локального запуска из `website/` скопировать шаблон в PowerShell:

```powershell
Copy-Item .env.example .env.local
```

Указать свой ключ в `LLM_API_KEY` файла `.env.local` и запустить:

```sh
node --env-file=.env.local server.mjs
```

Нужен Node.js 20.6+. Файл `.env.local` игнорируется Git и не раздаётся веб-сервером. В коммит входит только пустой шаблон `.env.example`. Вместо файла можно передать переменные окружения обычным способом и использовать `npm run dev`.

Необязательные `LLM_CACHE_DIR` и `LLM_AUDIT_PATH` задают папку дискового кэша и файл аудита **вне репозитория**. Без них кэш работает в памяти, журнал не записывается. Аудит содержит этапы, длительность, число токенов и код ошибки, без ключа, текстов запросов и внутренних рассуждений модели. Дисковый кэш содержит результаты анализа, поэтому доступ к нему должен быть ограничен локальным пользователем.

### Обработка запроса

1. Сервер проверяет компанию и доступность новости в её ленте. Тексты, профиль и баллы получает сам из API, не доверяя присланным браузером данным.
2. Модель составляет план и выбирает порядок обращения к ограниченному набору инструментов. Исполняются только чтение профиля, новости, оценки и связанных материалов банка; URL и команды модель не задаёт.
3. На основе собранных источников модель создаёт JSON с объяснениями, условиями, действиями и ссылками на основания. В модель передаются агрегаты, без выручки с неизвестной единицей, ID контрагентов и строк платежей. Сырые объяснения эвристических правил не используются как факты.
4. Сервер проверяет схему и ID источников; отдельный запрос к модели проверяет обоснованность. Если есть ошибки, выполняется одна попытка исправления и повторная проверка. Не прошедший проверку результат не показывается.
5. Результат кэшируется на шесть часов. Ключ кэша зависит от модели, версии обработки и содержания источников. Повторные одновременные запросы одной пары не запускают отдельную генерацию. Изменение исходных данных сбрасывает соответствующий кэш.

Разбор запускается по запросу пользователя; при открытии всех карточек генерация не выполняется. Первый вопрос может создать разбор, последующие используют кэш. Сервер ограничивает число одновременных обращений к модели и частоту вызовов. Начатый сервером разбор может завершиться и попасть в кэш после закрытия карточки; браузер отменяет ожидание и игнорирует запоздавший ответ.

По инструкции организаторов общий лимит команды — 500 рублей в день, сброс в 03:00 МСК. Фактический бюджет контролирует провайдер; сервер не оценивает остаток по неподтверждённым тарифам. Ошибки бюджета, доступа, частоты, таймаута и проверки показываются без раскрытия ответа провайдера или ключа. В режиме DeepSeek отключено отдельное скрытое рассуждение, чтобы не расходовать лимит на него; планирование и проверка выполняются отдельными запросами.

### Методы сайта

- `GET /api/ai/status` — готовность подключения и название модели, без секретов.
- `POST /api/ai/analysis` — `{ "companyId": "U_258131", "newsId": "N3" }`.
- `POST /api/ai/chat` — те же ID, `question` и до шести элементов `history` вида `{ "question": "…", "answer": "…" }`.

Для POST требуется JSON. Межсайтовые запросы и неизвестные Host отклоняются. Остальные `/api/` остаются прокси только для GET/HEAD. Для публичного размещения необходимы полноценная аутентификация, права на профили и индивидуальные лимиты: локальные проверки Origin их не заменяют.

## Файлы

- `dist/` — интерфейс, адаптер API, стили, изображения и шрифт.
- `dist/api.js` — HTTP-запросы и преобразование ответа API в данные карточек.
- `dist/feed-app.js` — отображение ленты и взаимодействия.
- `dist/news-tools.js` — фильтрация, основания отбора и сериализация экспорта.
- `dist/news-reader.js` — разбор, диалог и обратная связь.
- `dist/feed-tools.js` — фильтры, выбор карточек, экспорт и сравнение компаний.
- `dist/ai-reader.js` — состояние разбора, выводы, ссылки на основания и этапы обработки.
- `server/llm-client.mjs` — серверный клиент моделей и безопасные сообщения об ошибках.
- `server/insights.mjs` — планирование, инструменты, проверка, кэш и диалог.
- `server.mjs`, `package.json` — локальный сервер, прокси и проверка JavaScript.
- `data/demo_profiles.json`, `data/feed_preview.xlsx` — исходные данные команды; сервер эту папку не раздаёт. В браузере используются ответы API, а не эти файлы.
- `THIRD_PARTY_NOTICES`, `dist/assets/manrope-license.txt` — источники и лицензии.

Сайт с API запускается через `server.mjs`; простого размещения `dist/` на статическом хостинге для этой версии недостаточно. Для будущего хостинга нужно также настроить доступ к API.

## Проверка

```sh
npm run check
```

В браузере: переключить все четыре компании и сверить ленты с API; совместить фильтры и поиск; проверить неправильный период, выбор карточек и обе выгрузки; сравнить одну новость у разных компаний; сохранить оценку и диалог, повторно открыть карточку; проверить мобильное меню, вкладки с клавиатуры и ошибки при отключении бэкенда.

При настроенной модели открыть карточку и нажать «Подготовить разбор». Проверить влияние, рекомендации, основания и этапы обработки; задать вопрос и уточнение; повторно открыть ту же карточку и проверить кэш. Сменить компанию и убедиться, что её разбор и история не смешиваются с предыдущей. Без ключа вместо выдуманного ответа должна появиться ошибка подключения. Каждый новый разбор и вопрос расходует общий лимит API команды.

## Ограничения

Текущий бэкенд использует подготовленные новости и правила. Модель интерпретирует их, но независимый внешний поиск и автоматический сбор новых новостей пока не подключены. Содержательную достоверность не гарантируют ни проверка JSON, ни второй запрос к той же модели. Оценки означают релевантность, а не вероятность риска.

Записи `A_Nx` в текущем `/api/NewsAnalytics` получены из подготовленных примеров без подтверждённого источника и даты; они не выдаются за официальную позицию банка. Материал можно подключить, если API передаст `newsId`, `verified: true`, `sourceUrl`, `publishedAt` и `expertStance`. Ссылка должна вести к первоисточнику, её наличие само по себе не доказывает достоверность. Без такого материала раздел честно сообщает, что позиция банка недоступна. Обратная связь пока не сохраняется на сервере.

Исходные профили и ответы API содержат выручку и платёжные связи. Новости и объяснения показаны без независимой проверки фактов.

## Состав репозитория

Коммитить только сайт, исходные XLSX/JSON проекта, необходимые средства запуска, документацию и лицензии. Отчёты, скриншоты, временные файлы, базы SQLite, локальные настройки и рабочие материалы агента не включать. Перед каждым коммитом проверять состав изменений; `.gitignore` не обходить принудительным добавлением.
