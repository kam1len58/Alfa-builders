# Альфа-Бизнес

Статический прототип персональной новостной ленты: четыре профиля компаний, события из Excel, фильтры, поиск, подробности и сохранённое. Сборка и установка JavaScript-зависимостей не нужны.

## Запуск

Нужен Node.js 20 или новее:

```sh
npm run dev
```

Открыть http://127.0.0.1:4173. Порт задаётся переменной `PORT`.

## Файлы

- `dist/` — готовый сайт: HTML, CSS, JavaScript, данные для браузера, изображения и шрифт. Для статического хостинга используется только эта папка.
- `data/demo_profiles.json` и `data/feed_preview.xlsx` — переданные исходные данные. Сервер не раздаёт эту папку.
- `scripts/import_preview.py` — преобразование исходных данных в `dist/data/feed-preview.js`.
- `server.mjs`, `package.json` — локальный запуск и проверка JavaScript.
- `THIRD_PARTY_NOTICES` и `dist/assets/manrope-license.txt` — сведения об источниках и лицензиях.

## Обновление данных

После изменения файлов в `data/` запустить из папки проекта (нужны Python, pandas и openpyxl):

```sh
python -m pip install pandas openpyxl
python scripts/import_preview.py
npm run check
```

Импорт сверяет профили, назначения, оценки и видимость событий на двух листах Excel. Готовый файл `dist/data/feed-preview.js` входит в репозиторий, поэтому для просмотра сайта Python не требуется.

## Ограничения

Это подготовленная лента без автоматического сбора новостей, серверной авторизации и LLM. Четыре из пяти текстов обрываются в исходной таблице; продолжения не добавлялись. Ссылки на публикации и банковские материалы не предоставлены. Оценки из таблицы означают релевантность, а не вероятность риска. Данные компаний и утверждения в новостях не проверялись независимо.

Профили содержат выручку и платёжные связи. Они входят и в исходные данные, и в браузерный набор; доступ к репозиторию и опубликованному сайту нужно предоставлять с учётом этого состава.

## Состав репозитория

Коммитить только сайт, исходные XLSX/JSON проекта, необходимые средства запуска и обновления, документацию и лицензии. Отчёты, скриншоты, концепты, временные файлы, локальные настройки и рабочие материалы агента не включать. Перед каждым коммитом проверять состав изменений; `.gitignore` не обходить принудительным добавлением.
