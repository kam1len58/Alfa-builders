# Подключение ML

Модуль перенесён из ветки `ml`, коммит `2b2e7a1684a421b825a4ebe20d638c875826aa77`. Извлечение фактов, движок 25 правил и мультиязычные эмбеддинги подключены через `src/worker.py`. Ключи из исходной ветки удалены из переносимой копии; базы Chroma и журналы не переносились.

## Поток данных

Бэкенд .NET предоставляет профили и исходную ленту. Node проверяет доступ и получает зарегистрированную новость, профиль и подтверждённые источники. Python извлекает факты Gemma, применяет правила, ищет фрагменты банка через ChromaDB и `intfloat/multilingual-e5-small`, формирует разбор DeepSeek и выполняет самопроверку. Затем Node проверяет буквальные цитаты и признаки, а Qwen проверяет смысл; при необходимости выполняются исправления. Диалог использует проверенный разбор.

Балл карточки сохраняется из сервиса данных; оценка ML, правила и найденные фрагменты доступны в `analysis_payload.ml` и `/api/trace`. Оценки не усредняются и не называются вероятностью риска. В RAG попадают только переданные сайтом материалы `kind=bank, verified=true`, с ID, ссылками и датами. Эталонные `alfa_view` из golden_news.json не используются как подтверждённая позиция банка.

## Установка

Нужен Python 3.12. Из website выполните `npm run setup:ml`: скрипт создаст окружение в `APP_DATA_DIR/ml/venv` (по умолчанию — в пользовательской папке runtime вне проекта), установит зависимости и заранее загрузит модель эмбеддингов. Можно подготовить окружение вручную через `pip install -r website/ml/requirements.txt` и указать интерпретатор через `ML_PYTHON_EXE`. Включение — `ML_ENABLED=1`; единый `npm start` включает интеграцию по умолчанию. Для прежнего Node-режима можно явно задать `ML_ENABLED=0`.

ML не слушает порт. Запросы идут по закрытым каналам родительского процесса. Python не получает API-ключ: модели вызываются через Node с общим учётом токенов, частоты и бюджета. Сбой ML возвращает явную ошибку, подготовленный ответ не выдаётся за модельный.

Эмбеддинги загружаются при первом поиске; модель, векторная база и метаданные трасс хранятся в `APP_DATA_DIR/ml`, вне Git. Полные вопросы и профили в журнал worker не записываются. Тяжёлые зависимости ML требуют отдельной проверки ресурсов при размещении; текущая интеграция локальная.

## Проверка

`python -m unittest discover -s website/ml/tests -p test_integration.py` проверяет защиту источников и схему без платных вызовов. Исходные тесты правил: установить `pytest`, из website/ml выполнить `python -m pytest tests/test_rule_engine.py`. Это регрессии на эталонах, не независимая оценка точности. Реальный разбор и поиск проверяются отдельно; фиктивные экспертные оценки не создаются. Compose использует Dockerfile.ml; контейнерная сборка этой интеграции требует отдельной проверки.
