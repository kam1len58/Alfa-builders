# Контроль качества

Разделяем работоспособность кода, релевантность отбора, обоснованность AI и пользу для руководителя. Метрики одного вида не заменяют остальные.

## Автоматические проверки

Дополнительно проверяются объединение перепечаток без сложения баллов, раздельные заседания/страны/прогнозы, сохранение прежних ID, косвенный отраслевой контекст, общий API и ограничения доступа к trace. Учёт токенов проверяется в том числе при обрезанном ответе; резерв бюджета — при параллельных запросах.

Precision@5 в сервисе и файле оценки требует всех пяти человеческих меток одной компании. Неполные метки показываются отдельно. Пересечение топ-5 — Jaccard последних лент разных разделов ОКВЭД; само по себе оно не подтверждает качество. Открытия источников/диалог считаются среди уникально открытых карточек в ограниченном окне метаданных.

Счётчик стоимости не восстанавливает вызовы до его включения. Цены без подтверждённого тарифа не подставляются; потерянный ответ/usage имеет неизвестную стоимость. Ручная оценка локального владельца не считается доказательством независимости эксперта.

npm test использует временные данные, подставной LLM и HTTP API. Тестовые отзывы не попадают в рабочую статистику.

data/quality-benchmark.json содержит переданные 120 синтетических примеров для 16 профилей. Прежние 24 сохранены в data/quality-regression.json. Есть положительные, нерелевантные и неоднозначные случаи. Precision = TP/(TP+FP), recall = TP/(TP+FN), accuracy = (TP+TN)/N. Нет знаменателя — нет данных.

Оба набора использованы для проверки/доработки правил: это регрессионный контроль, не независимое доказательство качества на неизвестных событиях. usedForTuning=true и independentValidation=false показываются явно. Benchmark выполняется при старте, раз в сутки работающего сервера и вручную. Тревога - precision или recall ниже 85%. Проверяется видимость при пороге score >= 0,4, не просто наличие сработавшего правила.

## Метрики AI и продукта

- Связь с источниками: доля выводов с проверенными цитатами/признаками. Не мера истинности.
- Использование банка: доля принятых разборов с проверенным банковским основанием.
- С первого раза: доля принятых разборов без исправления. Кэш не создаёт новую генерацию.
- Ошибки: доля отклонённых или неудачных попыток. Не частота фактических ошибок принятых ответов.
- Польза и сообщения об ошибках: доли серверных отзывов; выборка добровольная и смещённая.
- Экспертное одобрение: доля положительных экспертных оценок. Без оценок — «Нет данных».
- Отдельные экспертные критерии: фактическая корректность, применимость к компании и полезность действий. В знаменателе только оценки соответствующего критерия; null не считается положительным ответом.
- P95: 95-й перцентиль длительности завершённых генераций.

Предупреждения: >20% неудачных попыток после 10 попыток; >10% отзывов об ошибках после 10 отзывов. Статистика ограничивается доступными пользователю компаниями.

## Процесс

1. При изменении кода: синтаксис, тесты и benchmark; обязательные проверки должны проходить.
2. Ежедневно: источники, свежесть, ошибки, задержки, лимиты, новые отзывы.
3. Еженедельно: эксперт проверяет выборку новых событий и все сообщения «Есть ошибка» — факты, даты, контекст компании, условия гипотез, атрибуцию банка и разумность действий.
4. Оценку сохраняют в интерфейсе. Причину ошибки превращают в новый тест; изменения правил/промпта проверяют на прежнем и отдельном отложенном наборе.
5. Перед демонстрацией: новое событие → разные компании → разбор → основания → вопрос → экспорт; отдельно отсутствие источника и отказ модели.

Отзывы не меняют ранжирование и не дообучают модель автоматически. Подтверждение экспертом требует человека; тесты, Qwen и совпадение цитаты его не заменяют.

scripts/prepare-review.mjs формирует top-5 фактических лент четырёх разных разделов ОКВЭД и отдельную подвыборку скрытых новостей. Нужен запущенный локальный сервер. JSON и HTML сохраняются вне Git; все человеческие метки изначально пусты. --generate запрашивает до 20 разборов с расходованием командного лимита. scripts/score-review.mjs считает precision@5, корректность фактов и полезность действий по заполненным человеческим меткам и показывает знаменатели. Скрытая подвыборка помогает находить пропуски, но не даёт статистической оценки recall всего потока. Пакет с заполненным reviewer повторно не перезаписывается.
