# Архитектура и защита

Браузер → Node.js → API .NET для готовой ленты и исходных новостей. Профили поступают из локального CSV-каталога, а без него - из API .NET. Node.js также собирает материалы, хранит корпус, ранжирует новые события и управляет единым AI-сценарием. C# NewsInterpretationController не вызывается: разные генераторы не смешиваются.

## Анализ

Права и компания → профиль/событие → план → инструменты чтения и поиск → генерация DeepSeek → проверка JSON/цитат/признаков → смысловая проверка Qwen → принятие либо повторный поиск и исправление. Не более двух исправлений; повторный отказ выводится ошибкой.

Трасса включает план, инструменты и статусы этапов, без внутренних рассуждений. Историческая позиция банка, факты публикации и условные выводы модели представлены отдельно.

## Границы доверия

- Публикации, профиль и история — данные, не инструкции. Модель не выбирает команды, файлы, произвольные URL или получателей сообщений.
- Только HTTPS и точные хосты из конфигурации; внутренние IP и credentials в URL запрещены. DNS проверяется, IP закрепляется при TLS-запросе. Каждое перенаправление проходит те же проверки.
- Ограничены размер, время, число материалов и объём корпуса. DTD/ENTITY отклоняются; активный HTML удаляется, интерфейс экранирует текст.
- PDF извлекается в worker с пределом памяти и времени. Для сканов включены локальный рендер PDF.js и русский/английский OCR Tesseract; распознанный текст нового банковского документа всё равно требует проверки атрибуции и даты. Короткие утверждённые цитаты связаны с SHA-256 конкретного файла.
- В модель передаются агрегаты без строк платежей, ID контрагентов и выручки с неизвестной единицей. Отзывы не передаются модели.
- Цитата подтверждает происхождение фрагмента, а не истинность экономического утверждения.

## Права и запросы

Проверяются Host, Origin и Sec-Fetch-Site. Сессии в памяти действуют 8 часов; cookie — HttpOnly и SameSite=Strict. Изменения требуют CSRF-токен. Есть ограничения входа, AI, импорта и обновлений. Роли и компании проверяются сервером. Неизвестные API, произвольный прокси и запись в C# API отсутствуют.

Локальный режим доверяет пользователю компьютера и слушает loopback. Сетевой режим требует аккаунты. В Compose наружу опубликован только loopback-порт сайта, API остаётся внутри сети компонентов.

## Данные

company-context.mjs формирует ограниченный контекст отраслей контрагентов, группы и положения в датасете. events.mjs объединяет публикации с сохранением индивидуальных источников; постоянный eventIndex поддерживает прежние ID. contract.mjs и contract-api.mjs реализуют общий формат команды; legacy API остаётся доступным. Подробности — API_CONTRACT.md.

meter.mjs хранит технические метаданные вызовов обеих моделей и локальные резервы бюджета. Без подтверждённой цены стоимость неизвестна. quality.mjs хранит ограниченные снимки top-5 и события взаимодействия, проверяет область компаний пользователя; review-metrics.mjs считает метрики экспертного файла без заполнения пустых оценок.

Ключ — среда процесса или исключённый из Git .env.local. Аккаунты — файл scrypt-хешей вне Git. APP_DATA_DIR — атомарное хранилище, рассчитанное на один процесс: до 1000 материалов, 500 попыток анализа, 3000 отзывов, 1000 экспертных оценок и 2000 событий аудита.

analytics/build_profiles.py обрабатывает три CSV, агрегирует платежи и связи, вычисляет позицию в датасете и сохраняет профили вне Git. По умолчанию каталог содержит крупные компании. Конфликтующие ID исключаются со статистикой; null не заменяется нулём. Исходные CSV, полный граф и юридически не подтверждённые связи не передаются модели напрямую.

Параллельные записи сериализуются. Повреждённый файл не заменяется пустым. Два процесса не должны писать один APP_DATA_DIR.

AI-кэш содержит результаты и цитаты; повторное использование ограничено шестью часами. Кэш, корпус и отзывы не публикуются как статические файлы. Журнал содержит метаданные этапов, ID и длительности, без ключей, запросов и комментариев. Ошибки провайдера заменяются безопасными сообщениями.

## Промышленное размещение

Нужны SSO/OIDC, HTTPS/Secure-cookie, управление жизненным циклом аккаунтов, шифрование и резервирование, политика хранения, общая очередь/лимиты для нескольких процессов, согласованные права на источники и эксплуатационный мониторинг. Текущая реализация демонстрирует место механизмов безопасности в прототипе и не заявляет банковскую сертификацию.
