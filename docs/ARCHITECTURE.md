# Архитектура

## Компоненты

```
  Новости (RSS)               Данные банка (CSV)
       |                             |
       v                             v
+---------------+          +--------------------+
|   Backend     |<---------| analytics:         |
| сбор новостей |  профили | профили, матрица   |
| база данных   |          +--------------------+
| REST API      |
+---------------+
    ^        |  /analyze, /chat
    |        v
    |   +-------------------+       +---------------------------+
    |   |   ML-сервис       |------>| векторная база: материалы |
    |   |   (агент)         |       | Альфа-Банка               |
    |   +-------------------+       +---------------------------+
    |            |
    |            v
    |      разрешённые LLM
    |
+---------------+
|   Frontend    |
| Альфа-Бизнес  |
+---------------+
```

- **analytics** — строит профили компаний и бизнес-матрицу из данных кейса (см. [DATA.md](DATA.md)).
- **backend** — собирает новости, хранит их и готовые разборы, отдаёт данные интерфейсу, вызывает ML-сервис.
- **ml** — агент, который готовит разбор новости для конкретной компании.
- **frontend** — интерфейс в стиле Альфа-Бизнеса: лента, карточка новости, вопросы к разбору.

## Как работает агент

Разбор новости — не один запрос к модели, а последовательность шагов:

1. **План.** Агент определяет тему новости (ставка, курс, санкции, сырьё и т. д.) и решает, какие данные нужны.
2. **Инструменты.** Агент обращается к профилю компании, бизнес-матрице, поиску по материалам Альфа-Банка и графу контрагентов.
3. **Общий контекст.** Результаты шагов сохраняются и используются дальше, так что итоговый вывод опирается на одни и те же данные о компании и событии.
4. **Проверка.** У каждого утверждения должен быть источник: новость, материал банка или признак компании. Если источника нет или данные противоречат друг другу, агент повторяет поиск или прямо пишет, что данных недостаточно.

Все шаги записываются в журнал. По нему можно восстановить, какие источники и признаки компании повлияли на вывод.

## Где банк, а где модель

В карточке три блока:
- **Факты** — только то, что подтверждено источником новости.
- **Позиция Альфа-Банка** — только из аналитических материалов банка.
- **Вывод** — то, что сформировала модель на основе профиля компании и двух блоков выше.

## Экономия лимита

На модели действует дневной лимит. Поэтому разбор для пары «компания + новость» готовится один раз и сохраняется, а лента отдаётся из базы. Модель вызывается заново только для новых новостей и для вопросов пользователя. Новости с баллом ниже 0,4 до модели не доходят.

## Безопасность

- Ключ к моделям хранится только в переменных окружения.
- Интерфейс не обращается к ML-сервису и базе напрямую, только через API бэкенда.
- В модель передаётся профиль компании без лишних полей; идентификаторы в данных обезличены.
- Текст новостей передаётся модели как данные, а не как инструкции. Агент только читает данные и не может выполнять действия во внешних системах.
- Каждое обращение к инструментам и модели записывается в журнал.
- Расход токенов считается; при приближении к лимиту сервис отдаёт только сохранённые разборы.

## Масштабирование

- Новый источник новостей — новая строка в конфигурации.
- Новая отрасль или тип события — новое правило в бизнес-матрице, без изменения кода.
- Новый клиент — профиль строится автоматически из данных банка.
